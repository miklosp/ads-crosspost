# Category fields per marketplace

Snapshot 2026-09-26. Generated by `pnpm discover <p>` into `src/platforms/<p>.fields.json`.

## File format

```jsonc
{
  "platform": "vinted",
  "snapshot": "2026-09-26",
  "fields": {                      // every distinct field, keyed by the site's own field name
    "size#12": { "label": "Size", "type": "grid", "options": ["Men's sizes / S", "Men's sizes / L", …] },
    "material": { "label": "Material (recommended)", "type": "list", "multi": true, "max": 3, "options": […] }
  },
  "categories": {                  // every category path, the same text the flows click
    "Men / Clothing / Tops & t-shirts / Shirts / Plain shirts": { "required": ["size#12", "condition"], "optional": ["brand", "color", "material", …] }
  }
}
```

- `#2`, `#3`… on a key: the same site field with a different option list in some categories. For example, Vinted has 33 `size` grids and 4 `condition` lists.
- `options` are the labels the form shows, in the site's UI language. Copy them verbatim into `item.yaml`.
- Grouped options are flattened to `"Group / Option"`, e.g. `"Men's sizes / L"`. The flow clicks the part after the last ` / `.
- Fields without `options` are free text, numbers or search boxes.

Look things up with `jq` rather than reading the files (they are 20–700 KB):

```sh
jq '.categories["Kläder / Herrkläder / Skjortor / Flanellskjortor"]' src/platforms/tradera.fields.json
jq '.fields["clothes_size"].options' src/platforms/tradera.fields.json
jq -r '.categories | to_entries[] | select(.value.required | index("size")) | .key' src/platforms/vinted.fields.json
```

### Blocket

- Only `title` and `description` are mandatory at the model level. Everything category-specific is optional.
- Many categories expose a brand select such as `men_clothing_brand` or `laptops_brand`. The flow fills "Varumärke" from `item.brand` only when it's an exact suggestion match.
- **Skick (`condition`) depends on the 3rd level.** In clothing, "Kläder… / Herrkläder" has no Skick. "Kläder… / Herrkläder / Skjortor" does. That explains the old `condition` failures: the field only appears after `product_category` is picked.
- Furniture categories add `height`/`width`/`depth` (numbers, cm), `designer` and a brand select. Nothing fills these yet.
- The model also has `anonymous` (hide profile until contact) and `price.price_amount`. Both are form-wide.

### Tradera

- `condition` is required in 3543 of 3838 categories.
- **882 categories require something beyond `condition`.** The main ones:
  - `color`: 284 categories
  - `vehicle_brand`: 224
  - `clothes_size`: 199
  - `music_format`: 94
  - `vehicle_section`: 84
  - `jewelry_material`: 62
  - `gender` and `clothes_size_children`: 54 each
  - `shoe_size`: 22
- **The flow never sets attributes.** It relies on Tradera's photo autofill to guess them. That is why `garmin-fenix-6x` (requires `smartwatch_brand`) went through, and why clothing isn't posted to Tradera.
- `new_only` marks the 8 categories where `category-restrictions` returns `allowUsed: false`.
- Option labels are Swedish, translated from Tradera's attribute keys. For example, `color` `black` → "Svart", "multi" → "Flerfärgad".

### Vinted

- `condition` is required everywhere, but in four variants:
  - `condition`: the usual 5 options (1911 categories).
  - `condition#2`: **only "New with tags"** (66 categories).
  - `condition#3`: only "New with tags" / "New without tags" (56 categories).
  - `condition#4`: adds "Not fully functional" (456 electronics/appliance categories).
- `size` is required in 607 categories, using 33 different grids. Clothing grids are grouped ("Men's sizes / L"); shoes and watches aren't.
- `brand`, `color` and `measurements` come back with no per-category config (`type: "global"`):
  - `brand` is the search box.
  - `color` is the global colour list the skill already carries (1–2 required in practice).
  - `measurements` is not handled.
- Rare required fields:
  - `video_game_platform` (5)
  - `computer_ram`, `computer_storage_capacity`, `internal_memory_capacity` (2 each)
  - `sim_lock`, `laptop_charger_included`, `skirt_length`, `video_game_ratings` (1 each)
- `isbn` is optional in book categories.

- The title is checked on submit only: "Title contains too many capital letters" (12 capitals refused, 8 accepted). The `post-ad` skill caps titles at 8.
- Validation errors appear as `role=alert` inside `<main>`. `vinted.ts` reads them (`formErrors`): before submit, and in a race with the page leaving the form. A refusal records `failed`, not `submitted`.

### Facebook

- `Condition` is required in all 24 categories except Garage Sale. No other field is required.
- Optional detail fields vary by category and sit under "More details". The flow only fills `Product tags`. The skipped ones include:
  - `Brand` (text; typeahead in Health & beauty / Toys)
  - `Size` and `Color` (text)
  - `Material` (six different lists)
  - `Bicycle Type`, `Platform`, …

## Gaps these snapshots expose

These are also listed in the review summary.

1. **Tradera category attributes.** Clothing, shoes, jewellery, music and vehicles can't post reliably until a step fills required attributes from `platforms.tradera.attributes`.
2. **Vinted `new` → "New without tags".** Use `condition: new_with_tags` when tags are still on (added 2026-09-26). Plain `new` still fails in the 66 `condition#2` categories, which only offer "New with tags". In `condition#4` categories, `poor` could map to "Not fully functional" instead of "Satisfactory".
3. **Blocket clothing/shoes.** Skick only appears after `product_category` is set. A record without `product_category` silently posts with no condition.
4. **Facebook Brand/Size/Color.** Free-text fields that `item.brand` and `platforms.*.size` could fill cheaply.
